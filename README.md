I'm **Pleniluner / 清月**.

I write systems code in **C/C++**, build Android applications with **Kotlin**, and use **Python and MATLAB** for models, images, and signals. My work also reaches into assembly, compilers, digital hardware, and parallel computing.

I enjoy debugging a program down to its instructions, turning a mathematical idea into an implementation, and finding out what a recorded signal actually contains.

Outside computing, I'm an architecture student, amateur radio operator **BG7LBJ**, and someone with a soft spot for ink-wash painting, acoustic guitar, Key's stories, Touhou's music, and clear night skies.

## 🧠 What I can build

### Systems & compilers

<p>
  <img src="https://img.shields.io/badge/C_%2F_C%2B%2B-4F46E5?style=flat-square" alt="C and C++" />
  <img src="https://img.shields.io/badge/Assembly-0369A1?style=flat-square" alt="Assembly" />
  <img src="https://img.shields.io/badge/GDB_%2F_QEMU-0F766E?style=flat-square" alt="GDB and QEMU" />
  <img src="https://img.shields.io/badge/Flex_%2F_YACC-B45309?style=flat-square" alt="Flex and YACC" />
</p>

I can implement and debug the mechanisms behind an operating system: bootstrapping, interrupts, page tables, memory allocation, processes, system calls, scheduling, synchronization, and file-system interfaces.

Compiler work includes lexical analysis, parsing, abstract syntax trees, scope and type checking, intermediate representations, control-flow analysis, and register allocation.

In C++, I work with ownership, RAII, move semantics, templates, and the STL. When a program fails, I can investigate its stack, calling convention, object lifetime, and generated instructions.

### Processor design & parallel computing

<p>
  <img src="https://img.shields.io/badge/Verilog_%2F_VHDL-0F766E?style=flat-square" alt="Verilog and VHDL" />
  <img src="https://img.shields.io/badge/FPGA-7E22CE?style=flat-square" alt="FPGA" />
  <img src="https://img.shields.io/badge/CUDA-4D7C0F?style=flat-square" alt="CUDA" />
  <img src="https://img.shields.io/badge/ISPC_%2F_pthreads-0369A1?style=flat-square" alt="ISPC and pthreads" />
</p>

I can describe and simulate digital circuits, implement a pipelined processor, and handle forwarding, stalls, exceptions, and memory-mapped I/O.

For performance work, I use CPU threads, SIMD, and GPU kernels. I can examine synchronization costs, cache behavior, memory coalescing, shared memory, and the limits of parallel speedup.

My practical toolkit includes parallel scans, image and fractal computation, and graph workloads such as BFS and PageRank.

### Applications, networks & software engineering

<p>
  <img src="https://img.shields.io/badge/Android-047857?style=flat-square" alt="Android" />
  <img src="https://img.shields.io/badge/Qt-0F766E?style=flat-square" alt="Qt" />
  <img src="https://img.shields.io/badge/Django-14532D?style=flat-square" alt="Django" />
  <img src="https://img.shields.io/badge/TCP_%2F_UDP-0369A1?style=flat-square" alt="TCP and UDP" />
</p>

I build event-driven interfaces, handle application state and persistence, and connect clients to network services. This includes Android lifecycle behavior, Qt signals and slots, database access, background tasks, and responsive UI design.

With sockets, I account for message framing, partial reads, timeouts, and concurrent connections. I can trace a request through DNS, TCP/IP, and HTTP, and reason about routing, congestion, authentication, and transport security.

I use modular design, version control, tests, debugging, and profiling to keep applications maintainable as they grow.

### Algorithms, machine learning & search

<p>
  <img src="https://img.shields.io/badge/C%2B%2B-4F46E5?style=flat-square" alt="C++" />
  <img src="https://img.shields.io/badge/Python-0369A1?style=flat-square" alt="Python" />
  <img src="https://img.shields.io/badge/NumPy-0F766E?style=flat-square" alt="NumPy" />
  <img src="https://img.shields.io/badge/Lucene-B45309?style=flat-square" alt="Lucene" />
</p>

I work with trees, heaps, hash tables, string algorithms, graph algorithms, dynamic programming, network flow, and search. I can analyze their complexity and choose data structures around the actual workload.

For machine learning, I can implement classical models and neural networks, derive and check gradients, and evaluate results with appropriate data splits and metrics. My background includes classification, clustering, probabilistic models, CNNs, recurrent networks, and attention.

For information retrieval, I work with tokenization, inverted indexes, TF–IDF, BM25, and ranking. I pay attention to data leakage, failure cases, and what an evaluation actually measures.

### Graphics, imaging & signal processing

<p>
  <img src="https://img.shields.io/badge/Graphics-7E22CE?style=flat-square" alt="Computer graphics" />
  <img src="https://img.shields.io/badge/Image_Processing-BE185D?style=flat-square" alt="Image processing" />
  <img src="https://img.shields.io/badge/DSP-B45309?style=flat-square" alt="Digital signal processing" />
  <img src="https://img.shields.io/badge/MATLAB-0369A1?style=flat-square" alt="MATLAB" />
</p>

I can implement geometric transformations, camera models, ray tracing, path tracing, and spatial acceleration structures. For images, I work with filtering, resampling, feature extraction, and matching.

For signals, I use sampling theory, convolution, Fourier analysis, FFTs, FIR/IIR filters, and time-frequency analysis. I can investigate aliasing, spectral leakage, filter response, and modulation in code and in recorded data.

These are the parts of computing I bring into astronomy, audio, and radio experiments.

### Mathematics behind the implementations

My foundation includes **calculus, linear algebra, discrete mathematics, probability and statistics, stochastic processes, complex analysis, and numerical analysis**.

I use linear algebra for geometry and models, probability for inference and noise, and numerical methods for approximation, optimization, integration, and differential equations.

I also care about the boundaries of an implementation: floating-point error, conditioning, convergence, computational complexity, and the assumptions behind a model.
